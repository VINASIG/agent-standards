# Develop VINASIG Agent Standards

This guide governs development of this repository. The consumer entrypoint is generated by the installer and documented in [the Codex adapter](adapters/codex/README.md).

- Read [README.md](README.md), [the integration contract](docs/integration.md), and the relevant policy before changing behavior.
- Preserve user work. Publishing, commit, push, account operations and changes outside a consumer repository require authorization for that action.
- Keep source, policies, skills, CLI output, commit subjects and public technical documentation in English. Answer a Vietnamese user in Vietnamese.
- Use SI agents in VINASIG copy. Preserve original names and identifiers of external tools.
- Treat version 0.1.0 as a public preview. A tagged release, npm publication, license grant or consumer rollout needs its own authorization. Do not silently impose draft design guidance on sibling repositories.
- Keep the installer offline, explicit about its target and pinned source digest, idempotent and reversible. Never bypass a local conflict or symlink boundary.
- Run `npm run check`, `npm test`, `npm run build` after implementation changes. Run `npm run verify:quality` when changing quality presets and `npm run test:web` when changing web enforcement. Inspect browser evidence when changing a fixture's visible behavior.
- Deliberately broken fixtures prove that gates reject defects. Fix a gate's bug without weakening its intended assertion. Rule, exception and baseline changes need a separate review rationale and changelog entry.
- Store local research, bundles, traces and screenshots in ignored `output/`. Durable audit summaries belong in `docs/audits/`.
- Keep the published standard independent of private asset archives, account tokens and personal machine paths.

- For new VINASIG website guidance or header/footer changes, maintain WEB-009, the project-start checklist and the generated consumer entrypoint together. Prove both web profiles route a fresh project to shared chrome without changing core consumers.
- For VINASIG project publication or public metadata changes, maintain CORE-009, `templates/project-publication.md`, the workflow skill and the generated entrypoint for every profile together. Route organization profile changes to `VINASIG/.github/profile/README.md` and its existing translation. Keep project facts consistent with the website inventory and repository details within authorized scope.
